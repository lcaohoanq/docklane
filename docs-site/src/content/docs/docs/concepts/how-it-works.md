Docklane has a control plane and a request data plane.

## Control plane

The controller discovers Docker workloads, stores route intent in SQLite,
reconciles that intent with current containers, and exposes one API used by the
CLI and Svelte UI.

Traefik polls a complete HTTP-provider document from Docklane. Docklane
validates each candidate document and persists the last known good snapshot.

## Request data plane

1. `dnsmasq` resolves `*.docker.home.arpa` to the local gateway.
2. The browser connects to Traefik on HTTPS port 443.
3. Traefik selects the route generated by Docklane.
4. Traefik reaches the workload through the shared proxy network.

Application containers do not need host port mappings.

## Reconciliation

Routes identify Compose project and service labels. When Compose recreates a
container, Docklane resolves the same selector, restores the required network
alias, and republishes the upstream.
