# Docklane v0.1.0-alpha.3

Docklane's third public alpha focuses on day-to-day usability. It introduces a
redesigned embedded web interface for operating and diagnosing routes, launches
the project documentation site, and automates delivery of verified releases to
the Arch User Repository.

## What changed

- Redesign the embedded UI with Tailwind CSS and DaisyUI while keeping the same
  controller API and route model.
- Open directly on an operational Routes view with readiness totals, search,
  clearer status labels, and compact per-route actions.
- Simplify route diagnostics with separate browser and controller results,
  actionable warnings, and technical details available on demand.
- Improve route creation and deletion with inline validation, explicit
  confirmation, unsaved-change protection, and safer keyboard focus.
- Add responsive layouts for desktop, tablet, and mobile, including accessible
  touch targets and loading, empty, failure, and retry states.
- Add persistent light and forest themes.
- Publish a complete documentation site covering installation, concepts,
  architecture, route management, diagnostics, configuration, upgrades, and
  troubleshooting.
- Automate `docklane-bin` metadata updates and AUR publication from the exact
  checksums produced by a tagged GitHub release.

## Install or update

Arch Linux users can install or update Docklane from the AUR:

```sh
yay -S docklane-bin
```

The package installs the release binary and declares its host dependencies; it
does not change DNS, certificate trust, Docker networks, or system services by
itself. Follow the
[installation guide](https://lcaohoanq.github.io/docklane/docs/getting-started/installation/)
to review and apply Docklane's managed host integration.

Users of other supported distributions can download the archive for their
architecture together with `checksums.txt` from the GitHub Release and verify
the checksum before replacing the binary. Release binaries select the matching
`lcaohoanq/docklane:v0.1.0-alpha.3` runtime image automatically.

## Reliability and development

- Add Playwright coverage for primary route operations, diagnostics, themes,
  error handling, and responsive layouts.
- Add `golangci-lint` checks for changed Go code and clearer Go test reporting
  in the repository CI gate.
- Add an integrated development workflow with Air live reload for Go and Vite
  hot module replacement for the web UI.
- Verify the documentation build and internal links in GitHub Actions.

## Compatibility

This release does not change the controller API, route persistence model, or
managed-install schema introduced by the earlier alphas. Existing routes and
installation manifests remain compatible.

## Supported hosts

- Debian 12 or Arch Linux with systemd.
- Docker Engine at `/var/run/docker.sock`.
- `dnsmasq` plus `systemd-resolved`.
- Linux `amd64` and `arm64`.

Docker socket access is equivalent to root-level control of the machine.
Install this alpha only on a development machine or VM whose local DNS, trust
store, Docker networks, and ports 80/443 Docklane may manage.

## Alpha limitations

- Local development domains only; purchased and public DNS are out of scope.
- Rootless and remote Docker engines are not supported.
- The controller UI/API binds only to `127.0.0.1:4646`.
- `docklane upgrade` migrates installation-manifest schemas; it is not yet a
  general binary or container-image updater.
- Automated certificate rotation and signed release provenance are post-alpha
  work.
